Analisis Arsitektur Sistem

1. Struktur Logic & Frontend

Sistem ini merupakan aplikasi Server-Side Rendering (SSR) berbasis Laravel 12 dan Tailwind CSS v4. Setiap perpindahan halaman membutuhkan loading/rendering halaman secara dinamis di sisi server.

Apakah ada logic frontend yang berat?
Tidak. Logic frontend hanya berupa script vanilla JS ringan (seperti jam realtime, kalender FullCalendar, modal popup). Penyebab utama loading lama bukan dari script frontend, melainkan dari delay koneksi aset dan overhead query sistem.

2. Hubungan Database terhadap Beban Sistem

Database MySQL terdeteksi aktif dan terhubung. Namun, saat ini data karyawan dan transaksi disimpan dalam Session.

Overhead Database di Level Sistem:
Meskipun data bisnis ada di session, berkas .env secara default menyetel CACHE_STORE=database dan QUEUE_CONNECTION=database. Karena database tidak memiliki tabel Laravel sistem (cache dan jobs), Laravel memicu query database error di latar belakang secara berulang pada setiap page load. Hal ini menambah beban rendering backend secara signifikan.

Indikasi & Rincian Masalah Loading Lambat

Karena berkas hot-reload public/hot tetap harus digunakan untuk proses development, berikut adalah rincian masalah dan solusi khusus agar proses pengembangan tetap lancar dan instan:

Penyebab 1: Vite Dev Server Tidak Berjalan Concurrently

Ketika Anda mengakses website via php artisan serve saja tanpa menyalakan server Vite, browser mencoba memuat aset dari URL dev-server (http://[::1]:5173).

  • Dampaknya: Karena port 5173 tidak aktif, browser mengalami delay timeout selama beberapa detik untuk setiap aset CSS dan JS sebelum akhirnya gagal dan memuat halaman secara lambat.
  • Solusi Utama: Jalankan perintah gabungan composer dev (menggunakan concurrently) agar Laravel Server dan Vite Dev Server berjalan bersamaan secara otomatis.

Penyebab 2: Delay Resolusi IPv6 [::1] di Windows

Secara default, Vite dev server seringkali binding menggunakan alamat IPv6 loopback [::1].

  • Dampaknya: Pada Windows, resolusi DNS lokal untuk alamat IPv6 sering mengalami delay lookup. Browser membutuhkan waktu lebih lama untuk terhubung ke http://[::1]:5173 dibandingkan IPv4 lokal (127.0.0.1).
  • Solusi: Konfigurasi server Vite di vite.config.js untuk memaksa penggunaan host IPv4 (127.0.0.1).

Penyebab 3: Overhead Cache Driver & Dynamic Blade Icons

Kombinasi antara driver cache database yang memicu query error (karena tabel cache tidak ditemukan di DB) dan proses compile template ikon Blade dinamis di sidebar menu secara berulang setiap request.

  • Dampaknya: Beban rendering di CPU server Laravel membengkak, memperlambat pembuatan halaman HTML di sisi backend sebelum dikirim ke browser.
  • Solusi: Alihkan driver cache ke driver file lokal (CACHE_STORE=file) dan jalankan optimasi caching pada ikon Blade.

Rencana Solusi Terarah (Vite Dev Server Tetap Aktif)

Rencana berikut dirancang untuk menjaga mode development Anda tetap berfungsi penuh sekaligus meniadakan delay loading:

1

Gunakan Host IPv4 pada Vite Config

Mengubah konfigurasi vite.config.js dengan menambahkan opsi server host agar Vite dev server secara konsisten berjalan di 127.0.0.1. Ini menghindari delay DNS resolusi IPv6 Windows.

2

Ubah Driver Sistem di .env ke Berbasis File / Sync

Mengubah CACHE_STORE=file dan QUEUE_CONNECTION=sync pada file .env. Solusi ini menghentikan loop error query database pada tabel cache/jobs yang tidak ada, sehingga performa backend kembali ringan.

3

Lakukan Caching Blade Icons

Jalankan perintah php artisan icons:cache agar ikon-ikon di sidebar dimuat instan dari cache memori tanpa memindai disk berulang kali.

4

Rekomendasi Jalankan Aplikasi dengan "composer dev"

Alih-alih menggunakan php artisan serve secara manual, gunakan perintah composer dev. Perintah ini akan meluncurkan Laravel server dan Vite dev server secara bersamaan, memastikan aset dimuat instan dan fitur hot-reload tetap berfungsi.
